# UI 对照：旧版 v0.29（WebView） vs 原生 1.0.0-alpha1

> **历史快照提示（2026-11-20 PST 补）**：下文保留当时基线、判断与后续旧回写，不代表 v1.7.9 现状，也不再滚动更新。当前状态/优先级见 [MASTER-PLAN.md](MASTER-PLAN.md)，本轮代码与 CI 核对见 [ASSESS-2026-11-20.md](ASSESS-2026-11-20.md)。

来源：用户提供的 8 张 v0.29.0 实机截图（聊天空态、抽屉、设置、插件、提示词模板、用量、余额、生图）。
用途：把"看起来像"变成"逐屏有据"。每条给出**旧版有什么 / 原生现在有什么 / 差什么 / 优先级**。

优先级口径：
- **P0** = 影响第一次使用能不能成功，或缺了会让人以为坏了
- **P1** = 高频路径上的信息密度差异（用一会儿就会觉得少东西）
- **P2** = 纯观感，不影响完成度

---

## 1. 聊天空态

| | 旧版 v0.29 | 原生 |
|---|---|---|
| 图标 | 渐变圆角块 + 应用图标 | 同（本轮已从 material Star 换回启动图） |
| 主文案 | 「你好，我是 AI Chat」 | 「有什么可以帮你？」 |
| 副文案 | 「一个应用，连接多家 AI 服务。支持插件扩展能力。」 | 「我可以回答问题、提供建议或帮你生成创意」 |
| 未配服务商 | 「开始之前」卡：3 步 + 大按钮「去设置 API Key」 | **本轮已补**（`empty-setup-card` / `empty-setup`） |
| 已配服务商 | 三条建议 pill（居中、按文字宽度） | 同（本轮已从撑满整行改成收口居中） |
| 顶部 | 应用图标 + 名称 + 副标题 + 两个 pill（`未配置服务商`、`用量`） | 标题 + 模型胶囊；**本轮已补**「未配置服务商」态，点击直达服务商设置 |

**结论：P0 已闭环。** 剩下 P2：旧版顶栏有 `用量` 快捷 pill，原生把用量放在 ⋮ 菜单里。

## 2. 抽屉

| | 旧版 v0.29 | 原生 | 差 |
|---|---|---|---|
| 新建 | 大号白底按钮「＋ 新对话」置顶 | 标题右侧「＋ 新对话」文字 | P2 |
| 搜索 | 「搜索对话」输入框 | 无 | **P1** |
| 空态 | 「还没有对话 / 点击上方「新对话」开始」 | 「还没有对话 / 点右上角「新对话」开始」 | P2 文案 |
| 分组 | 最近使用（可折叠）/ 设置 / 插件（已启用 4）/ 更多（可折叠） | 平铺列表 + 底部「助手库」「设置」 | **P1** 分组 |
| 快捷入口 | 助手（8 助手 · 6 提示词）/ 世界 / 模板（10 个）/ 生图 / 用量 / 余额 | 只有「助手库」「设置」两行 | **P1** |

**P1 建议**：抽屉加搜索框 + 「更多」分组（助手 / 世界 / 模板 / 生图 / 用量 / 余额），复用设置页已有的 `SettingsDestination`，几乎零风险。

## 3. 设置（一级）

| | 旧版 | 原生 | 差 |
|---|---|---|---|
| 结构 | 顶部四个 pill 页签：服务商 / 对话 / 高级 / 数据 | 枢纽页：四组卡片（模型与服务 / 能力 / 内容 / 数据） | 各有优劣，**不改** |
| 服务商行 | 彩色字母头像 + 名称 + baseUrl + 「未配置」状态 + 箭头 | 同类（`ProvidersScreen`） | P2 |

**结论**：这一屏原生信息组织更清楚，保持现状。

## 6. 用量页

## 本轮已落地的改动

1. **未配服务商时**：空态从「三条建议」换成「开始之前」三步卡 + 「去设置 API Key」按钮（`ChatScreen.SetupCard`）
2. **顶栏模型胶囊**：`settings.providers` 为空时显示「未配置服务商」，点击直达服务商设置
3. 空态图标换回 `ic_launcher_foreground`；建议 pill 按文字收口居中
4. 生图页「模型」从 `OutlinedTextField` 改成 `InputCard`，与上下两张卡片同形同高
5. 生图页参考图上限按服务商区分：新增 `ImageGen.MAX_REF_IMAGES_HARD = 16`，选择器放宽到 16，协议层仍按 OpenRouter 16 / 其余 10 切片；页内提示改为「OpenRouter 最多 16 张 / 其余只发第一张」

## 下一轮建议顺序（按性价比）

1. **抽屉**：搜索对话 + 更多分组（`ConversationDrawer.kt`，约 80 行）
2. **用量页**：按服务商 / 按对话分组（`UsageReport` 已有 `byModel`，照着加 `byProvider` / `byConv`，约 40 行 + 3 测试）
3. **模板页**：搜索 + 分类 chips + 行内星标（`LibraryScreens.kt`，约 100 行）
4. **插件页**：卡片加版本号 + 「当前对话」入口（`PluginsScreen.kt`，约 30 行）
5. **生图页**：参考图上限核对（读旧 `providers.js` 的 `input_references` 分支）+ 页内静态 Key 提示

以上都不动聊天主链路，风险低，可以和新页面任务并行。
